# GlassDigestor 0.6.0-pre-alpha.16

Development checkpoint, version code **22**; publication and current CI pending.
Pre-alpha.15 remains the published fallback.

PDFs recovered by PhotoRec/Binwalk or acquired from archives now have bounded
first-page thumbnails. The full in-app viewer shares the same owned-byte,
read-only descriptor and source-identity renderer. Logical PDF points and raster
pixels are explicit; small documents render at a useful resolution. Fit/Actual
pixels and horizontal/vertical scrolling preserve manual control, with page,
view and scroll position retained across recreation. Source details expand on
tap and a compact-phone case preserves actual document space.

Exact file bytes, typed saves, native findings and origin exports remain
available. Unknown extents do not decode; automatic PDF thumbnails have a
32 MiB file limit, while the full viewer retains the 256 MiB owned-input cap.
Pixel bounds do not bound native parsing time or internal memory.

Seven new host/real-libarchive/widget cases cover descriptor/range/cleanup/
mutation/budget/geometry, thumbnails and exact saves, page/view/position
recreation, compact viewports and stale navigation. Independent Python verifies
the two-page red/green vector fixture and old recovery bytes. The new ninth
Android lab case compiles and requires actual native recovery, both known page
colors, thumbnail and full-view sizes, source/UID/range identities and cleanup
on API 26/35; actual execution is pending.

Host UI classes now run serially in separate JVMs so shared Robolectric SDK/
animation state cannot stall a later class; every existing test/assertion is
retained. Production build flags, identity, signing and permissions are unchanged.

See [PDF preview contracts](../pdf-page-previews.md). Full host/ARM64/runtime/
source CI verification is recorded separately before publication. Production
ARM64/handset/SAF/full UI and arbitrary PDF acceptance remain unverified.
