# Feature parity and verification

GlassDigestor targets desktop Detect It Easy functionality, then extends it with
Android package investigation and file recovery. Implemented functionality and
verified behavior are separate: **host** means engine/JNI fixtures or Robolectric
checks; **platform** means the specifically named actual Android contracts.
Neither establishes production ARM64, full interface or real document-provider
acceptance. Partial coverage and pending work remain explicit below.

## Upstream comparison boundary

The inventory is anchored to CDiE `f055daa56fd3feef1db4d6dbc187cb292de24ea9`
and Detect It Easy/database `7ef816ee64ee36b4884da6b930a11542742affb7`:
[desktop feature inventory](https://github.com/horsicq/Detect-It-Easy/blob/7ef816ee64ee36b4884da6b930a11542742affb7/README.md),
[CDiE overview](https://github.com/horsicq/CDiE/blob/f055daa56fd3feef1db4d6dbc187cb292de24ea9/README.md),
[database behavior](https://github.com/horsicq/CDiE/blob/f055daa56fd3feef1db4d6dbc187cb292de24ea9/docs/DATABASE.md)
and [native limitations](https://github.com/horsicq/CDiE/blob/f055daa56fd3feef1db4d6dbc187cb292de24ea9/docs/LIMITATIONS.md).

Format recognition, a script API, a structured viewer and full format validation
are separate capabilities. The pinned core recognizes more formats than its
complete native inspection tools parse. PE/.NET heuristics, anti-analysis,
Authenticode correlations, integrity checks, toolchain/DRM/debug/filename and
other database results require output comparison with Qt; loading the same
scripts is insufficient. One upstream comparison found an additional VMProtect
record in the Qt reference. Byte-string/UTF-16 semantics, unavailable
decompression helpers, validator stubs and incomplete instruction coverage also
remain material comparison limits.

CDiE recursive signature scanning expands ZIP-family containers within its
documented bounds; 7z/RAR/CAB/ISO member expansion and ZIP64 remain unsupported
by that scanner. Some allocation/temporary-space/member failures can skip a
member without a diagnostic. This does not describe the separate libarchive
browser, whose supported readers, bounds and acquisition failures are explicit.
Android reports disclose the scanner coverage limit rather than claiming that
the separate browser makes recursive signature scanning complete.

Automatic network database updates are deliberately absent. Local read-only,
offline investigation remains the product boundary; desktop updater network
behavior is not an Android parity target.

## Offline database boundary

Custom imports accept supported format folders at the root or beneath `db/` or
`db_custom/`; helpers, tag metadata and notices remain available. Unsupported or
nested format folders, non-script payloads, unsafe/duplicate paths, corrupt CRCs
and exceeded budgets fail visibly. Current bounds are 32 MiB compressed,
64 MiB expanded, 1 MiB per file and 10,000 entries. A native load must yield
signatures before activation; immutable prior snapshots support rollback.
Activation establishes neither every rule's correctness nor complete Qt/API
compatibility. Detailed build/test commands and current next steps stay in
[continuation](continuation.md), rather than accumulating release stories here.
